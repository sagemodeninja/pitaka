# Development documentation and devlogs

- Follow the [documentation rules](docs/rules.md) when writing or updating docs.
- Whenever the developer works on a Pitaka topic with an agent, update the relevant page under `docs/develop/`. This applies to discussions, questions, and design exploration as well as code changes.
- Use the closest existing page and add a section if needed. Create a new page only when the topic has no natural home, and link it from the [development index](docs/develop/README.md).
- Include the sentence “This acts as both official documentation and devlogs.” near the top of each page you update. Keep verified behavior in the documentation and record proposals, decisions, and open questions in the devlog.
- Summarize the substance of the discussion in brief entries. Fold clarifications and follow-ups into an existing row when they belong to the same thread and the summary still preserves the sequence. Add a timestamped row for a distinct topic, a meaningful change of direction, or a milestone worth tracking separately.
